定制与标准组成カスタマイズと標準構成Customization & Standards

⚠ 重要声明：讲的是「通用概念」，不是某个特定产品重要：これは「汎用概念」であり特定製品の話ではないImportant: these are generic concepts, not any specific product

本页从 Claude Code / Codex / Copilot / OpenCode 等同类工具中抽象出共通的概念模型。各工具的命名与实现各异，但底层构件相通——理解了概念，换任何工具都能迁移。本ページは Claude Code / Codex / Copilot / OpenCode などから抽出した共通の概念モデル。名称や実装は製品ごとに異なるが、底層の構成要素は共通——概念を掴めばどのツールにも応用できる。This page abstracts a shared conceptual model from tools like Claude Code / Codex / Copilot / OpenCode. Names and implementations differ per tool, but the underlying building blocks are common — grasp the concepts and they transfer anywhere.

Building Blocks

通用定制构件汎用の構成要素The Building Blocks

Rule / Instruction

项目级指令与约定（如 AGENTS.md 类规则文件）。プロジェクト規約（AGENTS.md 等）。Project-level rules & conventions (e.g. an AGENTS.md-style file).

类比類比like 员工手册就業規則employee handbook

Reference / Context

上下文、文档引用、记忆（memory）。文脈・ドキュメント参照・記憶。Context, doc references, memory.

like 随身资料袋資料バッグa satchel of reference docs

Command

自定义斜杠命令，封装常用流程。カスタムスラッシュコマンド。Custom slash commands wrapping routines.

like 快捷宏マクロa keyboard macro

Skill

可复用能力包（指令+脚本+资源）。再利用可能な能力パック。Reusable capability packs (instructions+scripts+assets).

like 可插拔技能卡差込式スキルカードa plug-in skill card

Agent / Subagent

主代理与子代理分工；子代理隔离上下文，且同样能调用工具与技能。主・子の分業；子は文脈を分離しつつ、ツールやスキルも使える。Main + subagents; subagents have isolated context and can use tools/skills too.

like 专项外包小组専門の外注チームa specialist sub-team

Hook

生命周期钩子，不止拦截工具：在 prompt/编辑/工具/提交/结束等事件上做格式化、检查、通知、阻断危险操作。ライフサイクルフック、ツール以外も：prompt/編集/ツール/コミット/終了等で整形・検査・通知・ブロック。Lifecycle hooks — not just tools: on prompt/edit/tool/commit/stop events, do formatting, checks, notifications, blocking risky actions.

like IFTTT + 质检 + 通知IFTTT + 検査 + 通知IFTTT + QA gate + alerts

Script / Tool

脚本与工具；MCP 作为通用「工具接入协议」。スクリプトとツール；MCP は汎用「ツール接続」。Scripts & tools; MCP as the generic "tool connector."

like 工具界的 USB-Cツールの USB-CUSB-C for tools

Evals

测「全轨迹」（工具选择 + 结果），不只看最终答案。「全軌跡」（ツール選択＋結果）を評価。最終回答だけ見ない。Test full trajectories (tool choice + outcome), not just the final answer.

Interop Protocols

Agent 互操作协议（标准化层）Agent 相互運用プロトコルAgent Interop Protocols

这些协议是 agent 生态的「连接标准」，分层互补、非竞争：UI ↔ agent ↔ agent ↔ 工具，各管一层。これらは agent エコシステムの「接続標準」。階層的に補完し合い、競合しない：UI ↔ agent ↔ agent ↔ ツール。These are the ecosystem's connection standards — complementary layers, not competitors: UI ↔ agent ↔ agent ↔ tools.

The Harness

Harness = Model + 这些构件的总和これら要素の総和all of the above

Agent = Model + Harness

精确定义：harness 是包裹模型、把「会回答」变成「会在循环里行动」的运行时机制——调用模型、分发工具调用、管理上下文、执行安全策略、失败恢复的那个循环；以及它驱动的 prompt、工具、钩子、沙箱、子代理与反馈/恢复路径。正確な定義：harness はモデルを包み「応答」を「ループ内で行動」に変えるランタイム機構——モデル呼出・ツール分発・文脈管理・安全執行・失敗回復のループと、それが駆動する prompt・ツール・フック・サンドボックス・子エージェント・フィードバック/回復経路。Precise definition: the harness is the runtime machinery wrapping the model that turns "responding" into "acting in a loop" — the loop that calls the model, dispatches tool calls, manages context, enforces safety, and recovers; plus the prompts, tools, hooks, sandboxes, subagents and feedback/recovery paths it drives.

Orchestration把多个 agent 当作单元来管理，各自跑自己的 harness（多 agent 系统）。「agent 管理」属于这一层。複数 agent をユニットとして管理、各自が harness を持つ（マルチ agent）。「agent 管理」はこの層。Manages multiple agents as units, each running its own harness (multi-agent). "Agent management" lives here.
