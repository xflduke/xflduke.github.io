# Review Checklist（簡版）

## 仕様適合
- [ ] `docs/specs/<feature>.md` の受容基準すべてに対応する実装/テストがあるか。
- [ ] 未承認の仕様で実装していないか。

## 正確性 / 境界
- [ ] 金額・数量の計算がドメインルールに従うか。
- [ ] null / 0 / 上限 / 下限などの境界条件が網羅されているか。
- [ ] 状態遷移が仕様通りか（不正遷移を弾くか）。

## セキュリティ
- [ ] 秘密のハードコードがないか。
- [ ] 外部ネットワーク呼び出しがないか（オンプレ制約）。
- [ ] 入力検証（Pydantic スキーマ・型）がされているか。
- [ ] 認可・認証境界が守られているか。

## オンプレ制約
- [ ] 依存追加が許可リスト経由か。
- [ ] データが構内に留まるか。

## テスト
- [ ] 受容基準＝テストになっているか（仕様番号コメント）。
- [ ] 異常系・境界系のテストがあるか。

## 可読性 / 保守性
- [ ] レイヤ責務違反がないか（domain が外を import していないか）。
- [ ] 命名が glossary と一致するか。
- [ ] ログに秘密が出ていないか。

## 出力分類
- Must（merge 不可） / Should（推奨） / Nit（任意）。
